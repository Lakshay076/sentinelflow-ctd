## 1. Compliance Status Taxonomy

To satisfy strict evidentiary standards, each requirement is assigned exactly one of the following formal statuses:
1. **Implemented and independently verified:** Fully implemented, verified against empirical PCAP replays or published independent reference vectors.
2. **Implemented and unit-tested:** Implemented and validated through repository unit and integration test suites.
3. **Partially implemented:** Functional core implemented, but with documented protocol, cryptographic, or operational limitations.
4. **Not implemented:** Specified in challenge documentation or architecture roadmap, but no executable code exists in repository.
5. **Not independently verified:** Implemented, but lacks published external reference vectors or real-world empirical validation data.

## 4. Known Limitations and Unverified Claims

1. **QUIC Initial Payload Decryption (REQ-17):** Wire header metadata (Version, DCID, SCID, packet types) is implemented and verified. Initial CRYPTO frame decryption via RFC 9000 HKDF secrets is **not implemented**. ClientHello extraction does not function on real encrypted QUIC wire captures.
2. **Encrypted Client Hello (ECH):** In TLS 1.3 with ECH, the inner SNI is encrypted and unavailable to passive sensors. Outer SNI/grease values are parsed.
3. **ML Training Baseline (REQ-20):** Shipped Isolation Forest model is trained on synthetic data. Generates 2 false positives on benign browsing traffic.
4. **Router Telemetry Ingestion (REQ-25):** Direct NetFlow/IPFIX UDP collection is not implemented; PCAP replay and live interface capture are the supported ingestion paths.
5. **Single-Threaded GIL Bottleneck:** Prototype sustained throughput tops out at $\sim 500\text{ pps}$ ($0.67\text{ Mbps}$) under single-threaded Python/Scapy on Windows.
